01 / THE PROBLEM

Your AI remembers the conversation. Not the project.

A long project produces hundreds of decisions. Some hold, some get reversed, most end up buried in a chat log nobody reads again. The agent sees whatever fits in the window today.

Project knowledge changes. Context windows do not give those decisions a history.

{{ problemTimeline }}

CONTEXT ROT

Important project decisions disappear into old conversations. The constraint you agreed on in March does not travel to the prompt you write in September.

BLACK BOX ACTIONS

The agent edits files and runs commands. Working out why it did that means reading the diff yourself, every time.

LOST SYSTEM UNDERSTANDING

Architecture and history live in people's heads. New contributors, and agents, rebuild that picture by hand.

02 / WHAT REEVE DOES

Remember. Explain. Understand.

Three things, built on top of the coding agent you already use. Memory for the project, evidence for every action, and a live view of the system underneath.

MEMORY

Remember what your project has learned.

Decisions, constraints and conventions stored over MCP, with a clear line between current and superseded.

EXPLAIN

Show developers what the agent is actually doing.

Edits, creates, deletes, shell commands and test runs, explained from the real diff and the real output.

UNDERSTAND

See the system your agent is working inside.

Architecture generated from the repository, plus a Git history you can read and jump through.

MEMORY

Projects evolve. Your AI should remember that.

Reeve does not dump the entire history into every prompt. It retrieves what matters for the task in front of the agent.

03 / HOW IT WORKS

Reeve works around your existing coding agent.

Copilot keeps handling the coding agent workflow. Reeve adds memory, visibility, and project understanding around it.

Authentication, entitlement, model selection and usage limits stay where they already are. Reeve does not touch them.

Reeve unavailable?

Your coding agent keeps working. Every memory call and every explanation runs inside its own boundary, and a failure there never blocks a tool call.

04 / INFRASTRUCTURE

Built with AWS.

The memory layer runs outside the editor. These are the services it actually runs on, plus the one that hosts this page.

COMPUTE

Amazon EC2

What we use it for. Runs the Dockerized Reeve MCP backend, with Caddy in front as the reverse proxy and TLS terminator.

Why it matters. The editor holds an SSE connection open for the length of a session. A long-lived instance handles that better than a request-scoped runtime.

INFERENCE

Amazon Bedrock

What we use it for. Mistral Large 2 for memory reasoning, Titan Text Embeddings v2 for the vectors behind retrieval.

Why it matters. Retrieval decides what the agent sees. Keeping embeddings and reasoning on one managed endpoint means no model hosting to babysit.

WEBSITE ONLY

AWS Amplify

What we use it for. Building and hosting this page on push to main.

Why it matters. The product page is not part of the editor or the memory service. It ships on its own pipeline and shares nothing with them.
